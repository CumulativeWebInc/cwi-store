Verdict Ledger

An invalidation primitive for cached verification verdicts. Record, re-check, catch stale truth.

What it is: verification verdicts are snapshots, and snapshots go stale. Verdict Ledger records each verdict with sha256 snapshots of its evidence in an append-only local ledger, then re-checks that evidence on your schedule. The moment the evidence drifts or the TTL expires, it appends a superseding STALE envelope with the exact reason — evidence-drift:<source> or ttl-expired — and exits 1 for cron and CI gates. Unreachable evidence is an error, never a silent pass. Stdlib Python only: no dependencies, no telemetry, the only network traffic is the evidence fetches you point it at. Exit codes: 0 all current / 1 stale findings / 2 error. Default TTL is 30 days, matching the STALE rule CWI runs on its own Placement Wall.

What it is not: it never proves a verdict correct — CURRENT means the evidence has not moved since recording, nothing more, and every report says so. It is not tamper-proof: the ledger file is append-only by convention, not cryptography. The build-week receipts demonstrate two real stale catches (an evidence-drift catch over live HTTP and a TTL-expiry catch) plus one honest refusal, documented verbatim in the repo — check them before you buy.

What you get

  • verdict_ledger Python package (record, recheck, status, version subcommands; envelope schema cwi.verdict-envelope/1.0)
  • Append-only JSONL ledger: old envelopes are never rewritten — currentness is computed from each lineage's newest record, so the chain shows every correction
  • Text + JSON reports (cwi.verdict-ledger-report/1.0) naming exactly what went stale and why; 75-test suite, all green, verifiable in under 5 minutes
